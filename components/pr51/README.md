1) Яке призначення документації програмного коду та чим документаційні коментарі відрізняються від звичайних коментарів?

- Документація пояснює призначення та використання коду. Документаційні коментарі мають спеціальний формат для IDE й генераторів, а звичайні просто пояснюють код читачу.

2) За яких умов компілятор .net буде генерувати зауваження warning CS1591: Missing XML comment for...?

- Коли ввімкнене створення XML-документації, а публічний тип або його член не має XML-коментаря.

3) В яких випадках та як варто приглушувати зауваження warning CS159?

- CS1591 можна приглушити для згенерованого коду або там, де документація свідомо не потрібна, через #pragma warning disable/restore CS1591 чи NoWarn у .csproj. Для звичайного публічного API краще додати опис.

4) Як увімкнути автоматичне генерування XML-файлу документації в проєкті .NET?

- Додати `<GenerateDocumentationFile>true</GenerateDocumentationFile>` у PropertyGroup файла .csproj.

5) Які налаштування і де слід додати якщо сторінка swagger документації непоказує опис ендпойнту?

- У Program.cs налаштувати генерацію Swagger та опис маршрутів. Для Minimal API додати WithSummary і WithDescription, а для XML-коментарів підключити IncludeXmlComments у AddSwaggerGen.

6) Які налаштування і де слід додати якщо сторінка swagger документації непоказує опис схеми даних?

- Додати XML-коментарі до DTO та їхніх властивостей, увімкнути XML-файл документації й підключити його через IncludeXmlComments. Якщо DTO в іншій збірці, потрібен також XML цієї збірки.

7) Що таке JSDoc та які теги використовуються для документування функцій, параметрів і результатів їх виконання в JavaScript?

- JSDoc це формат коментарів для JavaScript. @param описує параметри, @returns результат, @throws помилки, @example приклад використання.

8) У чому полягають основні відмінності між XML-документацією C# та JSDoc у JavaScript?

- C# використовує XML-теги та може створювати XML-файл під час компіляції. JSDoc використовує теги з @, які читають IDE та окремі генератори документації.
