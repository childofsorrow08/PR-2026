1) Чим проєкт типу Class Library відрізняється від проєкту веб-застосунку й чому бібліотеку не можна запустити на виконання?

- Class Library містить код для інших проєктів і не має власної точки запуску, в той час як вебзастосунок запускає сервер.

2) Що таке рішення (solution) і чому воно не є проєктом?

- Solution об’єднує декілька проєктів та їхні налаштування. Сам по собі він не є окремою програмою.

3) Навіщо у VS Code потрібне розширення vscode-solution-explorer і що воно додає порівняно зі стандартним провідником?

- Воно показує структуру рішення та проєктів, а не просто файли на диску, і дає команди для роботи з ними.

4) Що саме дає проєкту посилання на інший проєкт під час компіляції та під час складання?

- Компілятор отримує доступ до публічних типів іншого проєкту, а система складання враховує залежність і складає його раніше.

5) Чому перелік DeliveryType винесено в окремий проєкт спільних типів, а не залишено в проєкті моделей?

- Щоб спільний тип можна було використовувати в моделях, DTO та бізнес-логіці без зайвих залежностей.

6) Що таке транзитивна залежність і чому проєкт PostService бачить клас Posting без прямого посилання на PostService.Models?

- Це залежність через інший проєкт. PostService посилається на BusinessLogic, а той на Models, тому тип Posting також доступний.

7) Чому посилання між проєктами не можуть утворювати цикл і що це обмеження дає архітектурі продукту?

- Цикл не дає визначити нормальний порядок складання. Відсутність циклів допомагає розділяти відповідальність між компонентами.

8) Чим простір імен відрізняється від збірки і чому їх зазвичай називають однаково?

- Простір імен групує типи в коді, а збірка це скомпільований файл DLL або EXE. Однакові назви використовують для зручності.

9) У якому порядку складаються проєкти під час компіляції всього рішення і хто визначає цей порядок?

- Спочатку складаються залежності, потім проєкти, які їх використовують. Порядок визначає MSBuild за посиланнями.

10) Як запустити на виконання конкретний проєкт рішення з командного рядка?

- Через `dotnet run --project шлях/до/проєкту`.
