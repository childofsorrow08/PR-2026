1) Яку роль виконує репозиторій у багатошаровому застосунку та чому доступ до бази даних виносять в окремий проєкт, а не звертаються до неї напряму з бізнес-логіки?

- Репозиторій виконує збереження та читання даних. Окремий проєкт дозволяє змінювати спосіб зберігання без переписування бізнес-правил.

2) Для чого потрібен метод, що піднімає міграції, і коли він має викликатися в застосунку?

- Щоб підготувати структуру бази перед роботою із записами. Його викликають при запуску до обробки запитів; у цій роботі CreateDb створює таблицю, якщо її ще немає.

3) Що таке рядок з'єднання (connection string) і за що відповідає об'єкт SqliteConnection?

- Рядок з’єднання містить параметри доступу до бази, а SqliteConnection відкриває й представляє з’єднання з нею.

4) Чим відрізняються методи виконання команди ExecuteNonQuery, ExecuteReader та ExecuteScalar, і за якою ознакою обирають потрібний із них для конкретного запиту?

- ExecuteNonQuery повертає кількість змінених рядків, ExecuteReader читає набір рядків, ExecuteScalar повертає перше значення першого рядка. Метод обирається за потрібним результатом.

5) Як задаються значення параметрів SQL-запиту і навіщо використовувати параметри замість підстановки значень безпосередньо в текст запиту?

- Через command.Parameters, наприклад AddWithValue. Параметри захищають від SQL-ін’єкцій і правильно передають значення різних типів.

6) Як через SqliteDataReader читають результат запиту SELECT, і чому перед читанням значення стовпця, який може бути NULL, потрібно перевіряти IsDBNull?

- Через цикл reader.Read() та методи GetInt32, GetString й інші. IsDBNull перевіряє NULL, щоб не читати його як звичайне значення.

7) Яким чином метод Create дізнається ідентифікатор, згенерований базою даних для нового запису?

- Після INSERT виконує SELECT last_insert_rowid() у тому самому з’єднанні й отримує результат через ExecuteScalar.

8) Яке значення повертає ExecuteNonQuery() під час виконання запиту DELETE, і як це значення використовує метод Delete?

- Кількість видалених рядків. Нуль означає, що запис не знайдено, а одиниця що його видалено.

9) Які зміни потрібно внести в PostingService, щоб він працював через IPostingRepository, і чому залежність оформлюють саме через інтерфейс, а не через конкретний клас PostingRepository?

- Прийняти IPostingRepository через конструктор і замінити роботу зі списком викликами репозиторію. Інтерфейс дозволяє замінювати реалізацію сховища.
