1) Що таке узагальнений інтерфейс і чим його оголошення відрізняється від оголошення звичайного інтерфейсу?

- Це інтерфейс із параметром типу, наприклад `IRepository<T>`. У звичайного інтерфейсу такого параметра немає.

2) Якими двома способами клас може реалізувати узагальнений інтерфейс?

- Можна вказати конкретний тип, наприклад IRepository<Posting>, або залишити параметр T у самому класі.

3) Чим відрізняється клас, що реалізує узагальнений інтерфейс із фіксованим типом-аргументом, від класу, що лишається узагальненим?

- Перший працює лише із заданим типом, в той час як другий можна використовувати з різними типами.

4) Для чого потрібне обмеження where T : BaseClass і що воно дозволяє робити всередині узагальненого класу?

- Обмеження дозволяє передавати BaseClass та його нащадків і звертатися до членів цього класу.

5) Чому інтерфейс IRepository<T> потребує обмеження параметра типу базовим класом Model, а не залишається зовсім без обмежень?

- Щоб репозиторій міг використовувати Id, який оголошений у Model.

6) Що станеться зі статичним полем узагальненого класу, якщо створити об'єкти цього класу з різними типами-аргументами?

- Для кожного окремого типу-аргументу буде своє статичне поле.

7) Чому дані, збережені в GenericRepository<Posting>, не змішаються з даними іншого узагальненого репозиторію, створеного для іншої сутності?

- GenericRepository<Posting> та репозиторій іншого типу мають окремі статичні списки.

8) Яку перевагу дає розробка одного узагальненого репозиторію порівняно з написанням окремого репозиторію для кожної сутності проєкту?

- Не потрібно повторювати однакові операції для кожної сутності, а правильність типів перевіряє компілятор.

9) Чому властивість Id виносять у спільний базовий клас Model, а не оголошують окремо в кожній сутності?

- Щоб усі сутності мали спільний ідентифікатор і не доводилося оголошувати його щоразу.
