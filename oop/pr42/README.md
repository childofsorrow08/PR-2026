1) Що відбувається з програмою, якщо виняток виник і не був перехоплений?

- Якщо обробник так і не знайдеться, програма зазвичай завершиться з помилкою.

2) Для чого застосовують конструкцію try-catch і як вона змінює хід виконання програми?

- У try виконується код, який може дати помилку, а відповідний catch її обробляє. Решта коду в try після помилки пропускається.

3) Чому блок catch (Exception ex) перехоплює винятки будь-яких типів?

- Тому що звичайні винятки .NET успадковуються від Exception, тому цей catch підходить і для їхніх підтипів.

4) Які винятки може згенерувати метод int.Parse і за яких умов кожен із них виникає?

- FormatException при неправильному форматі, OverflowException при виході за межі int та ArgumentNullException при null.

5) Які властивості об'єкта винятку дозволяють з'ясувати його тип, причину та місце виникнення?

- GetType() показує тип, Message описує помилку, StackTrace показує місце й послідовність викликів, InnerException містить вкладену помилку.

6) Чому порядок блоків catch має значення й що станеться, якщо блок catch (Exception) розташувати першим?

- Перевіряється перший відповідний catch. Якщо Exception поставити перед його підтипами, наступні блоки будуть недосяжними й компілятор видасть помилку.

7) Коли виконується код блоку finally? Чи виконається він, якщо виняток не було перехоплено?

- finally виконується при виході з try, зокрема через виняток, який цей catch не перехопив. При аварійному завершенні процесу це не гарантується.

8) Як за допомогою try-catch і циклу організувати повторне введення даних до отримання коректного значення?

- Помістити введення та int.Parse у try всередині циклу. При помилці показати повідомлення, а при правильному введенні вийти з циклу.

9) Чому порожній блок catch вважається небезпечним і в яких місцях програми перехоплення всіх винятків виправдане?

- Порожній catch приховує помилку. Загальний обробник доречний на рівні всього застосунку, щоб записати помилку й коректно завершити роботу.

10) Для чого призначений фільтр when і чим він відрізняється від перевірки умови всередині блоку catch?

- when перевіряє умову до вибору catch. Якщо вона хибна, пошук обробника продовжується, в той час як if виконується вже всередині вибраного catch.

11) Чому змінну, яка використовується в умові when, потрібно оголошувати поза блоком try?

- Змінна всередині try недоступна за його межами, тому when її не побачить.

12) У якому порядку слід розташовувати блоки catch з фільтром і без нього для того самого типу винятку?

- Спочатку catch з фільтром, потім catch для того самого типу без фільтра.
